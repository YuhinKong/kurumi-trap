# 股票监控Agent · V0.1增强版

基于桌面V0.1完善，适用Windows、Python 3.13和VS Code。仅做A股行情研究、规则筛选和风险计算，不访问券商、不自动交易、不保证盈利。本版不再依赖stockdb，不需要下载数GB数据库，暂不支持ETF。

## 桌面使用流程

1. 打开桌面“股票监控agent”文件夹，双击 **3-检查运行环境.cmd**。应显示“环境检查通过”。这只验证依赖、配置和SQLite写入，不代表外部接口正常。
2. 双击 **1-打开股票监控.cmd**，等待终端显示网址，在浏览器打开 `http://localhost:8501`（以终端实际输出为准），保留该窗口。
3. 初次可打开侧栏“模拟测试模式”，点“立即扫描”检查页面。模拟价格、日历均明确标注，独立数据库保存，不发送通知。
4. 关闭模拟模式，点“立即扫描”。默认自选601728中国电信、601668中国建筑、000498山东路桥、002376新北洋、600050中国联通、600004白云机场。逐股串行扫描可能需要数分钟，接口失败会等待超时和备用源，不要重复启动。
5. 总览查看行情时间、快照来源、日K来源、数据质量、日周趋势、突破/回踩、量比、风险收益比和最终状态；展开股票查看逐项依据、技术失效位、目标计算及错误原因。
6. 要自动扫描，再双击 **2-启动自动监控.cmd** 并保留窗口。“系统状态/日志”显示调度心跳。打开网页不会自动启动调度器；刷新页面可查看后台结果。
7. 结束时，在监控窗口按Ctrl+C，再关闭网页服务窗口。关机、休眠、断网或进程退出后不会继续监控，也不会补造错过的信号。

## 安装和验证

启动器只在缺少虚拟环境或依赖时安装，正常每天打开不会重复下载完整依赖。首次安装需网络和Python 3.13（加入PATH）。不要复制其他目录的.venv。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements.txt
.\.venv\Scripts\python.exe -m monitor.cli check
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m streamlit run app.py
```

VS Code选择本目录 `.venv\Scripts\python.exe`。也保留start.ps1和run-monitor.ps1；无需改变执行策略，受限时直接使用CMD启动器。

```powershell
# 实测行情源，不发通知；结果是测试当时快照，不是后续实时行情
.\.venv\Scripts\python.exe -m monitor.cli probe --all-sources --output validation-live.json
# 显式启用六只股票的真实接口测试
$env:RUN_LIVE_TESTS='1'
.\.venv\Scripts\python.exe -m pytest -q
Remove-Item Env:RUN_LIVE_TESTS
```

默认pytest跳过6项真实接口测试；启用后接口断开、日期过期或快照缺失会失败。双源真实价差超限时，测试检查“正确阻止”，不要求供应商一定报相同价格。测试结论及局限见VALIDATION.md。requirements-lock.txt记录本次环境，需重建相同版本时用它安装。旧check_external.py兼容入口也改为检查新版全部行情源。

## 数据层与真实性

- 日K顺序：**AKShare/东方财富 → 腾讯公开日K → AKShare/新浪日K**。接口失败、字段非法、日期过期或历史长度不足会继续备用源，单股失败不停止整个扫描。
- 快照顺序：**腾讯 → 新浪**，逐股获取供应商时间戳。候选必须再用独立上游核验；历史来源与快照来源分别展示。
- 5分钟线按需请求AKShare/东方财富，失败明确提示。日K不复权，除权除息可能造成跳变，需人工核验；周K从日K聚合，排除首个被截断的周及未完整本周。
- 成交量统一为手（100股），成交额为元。腾讯历史日K缺成交额时保留缺失，不以成交量乘价格冒充；风险计算可使用当日有效快照成交额，回测遇历史成交额缺失会阻止相应入场。
- 字段记录代码、名称、来源、上游身份、价格/OHLC、成交量、bar_time、fetched_at、timezone=Asia/Shanghai、盘中/完整标记、年龄、缓存标记。日K只有日期精度，不伪造逐笔时间。
- 盘中快照最大年龄默认180秒；缓存保留原始时间，明确标注，不能因重新读取缓存而变成实时。失败不以过期缓存代替实时数据。刷新页面会复核旧扫描年龄。
- 本机时间落后供应商几秒时，最多等待clock_wait_seconds=10秒，等本机实际到达行情时间才参与计算；保留原始时间并提示。更大偏差拒绝使用，请在Windows设置中同步时间；程序不修改系统时钟，未来数据不得参与计算。
- 双源默认价格误差不超过0.3%，时间差不超过120秒；缺源、过期、不同步均未确认。价差超限显示“数据源不一致”，阻止正式候选。
- 快照缓存15秒、历史缓存120秒；每源最多2次、间隔1秒，AKShare子进程单次总超时12秒，HTTP连接/读取超时有界，没有无限重试。

东方财富可能出现ProxyError/RemoteDisconnected或限流；备用源可用性同样受供应商影响。“系统状态/日志”可逐股检查。默认尊重代理；若确认本机代理失效，可仅对启动终端设置 `$env:MARKET_TRUST_ENV='0'` 后启动。本项目不修改系统代理。

## 策略与风控

突破：日线MA5>MA10>MA20>MA30、价格>MA5，完整周线同样多头；突破**此前20日**最高价（排除当前K），量比为当日量/此前5日均量，默认至少1.5。

回踩：相同日周趋势，最低价触及MA5或MA10附近（默认2%容差），收盘不低于开盘和前一日收盘，量比不超过1.1。盘中形态及成交量均未完成，只能产生预警。

规则输出通过、未通过、数据不足、数据错误；最终状态另显示观察、盘中预警、收盘确认、数据不足、数据过期、数据源不一致、数据错误。规则通过仍须日期、新鲜快照及双源通过；无规则候选显示“观察/无候选”，不因日线更新就宣称确认买点。

技术失效位来自最近10根当时已可见日K最低价，不按50元预算倒推。目标价为假设入场价加2倍技术价差，是情景假设而非预测。采用十进制0.01元报价、100股整数倍、1000元资金、50元风险预算、每边最低佣金5元、卖出印花税0.05%、默认0.1%滑点；其他费用可配置。扣费后的净风险收益比低于默认1.5时不通过预算筛选。

停牌、涨跌停、ST、上市阶段和财报风险不能单靠免费快照完全核实，真实扫描保留人工核验提示，全部风险通过的优先候选可能为空。“可负担100股”不等于可以买入。T+1、跳空、跌停可能使退出失败，50元不是实际最大亏损保证。

侧栏可增删自选、调整参数；完整默认配置见config.example.json，已有config.json会补齐新增项。比例使用小数。最多100只串行处理，建议从6只开始，不应对免费接口过度并发扫全市场。

## 交易日历和自动运行

真实交易日9:30–11:30、13:00–15:00按5分钟槽扫描，避开午休、周末、节假日。默认15:20后才允许当日日K完整；未覆盖日期保持未确认，至17:00每5分钟重试。日历不覆盖当天则拒绝猜测；刷新失败时仅允许7天内且覆盖当天的日历缓存并提示，这不放宽行情新鲜度。周K按该周最后交易日确认，支持节假日缩短周。

文件锁避免网页与调度同时扫描，每个项目最多一个调度器。SQLite保存行情缓存、扫描、错误和信号；按股票、策略、日期、预警/确认阶段去重。

如需自启动，可手动创建Windows任务计划：仅用户登录时运行，登录时触发；程序为本目录.venv\Scripts\python.exe，参数 `-m monitor.scheduler`，起始目录为本项目绝对路径，禁止重复实例。程序没有创建系统任务/后台服务。任务按配置可唤醒睡眠，不能保证关机继续监控。

## 回测与通知

“K线与回测”页提供日/完整周K、MA、成交量、按需分钟线和逐股回测。回测只使用当时历史生成信号，下一交易日开盘加滑点入场，次日起可卖；同根K同时触及目标和失效位优先失效退出，跳空按更差价，普通主板10%开盘限制保守阻止成交。

只适用普通主板研究；未建模盘口队列、历史ST变更、退市样本、历史财报、税率变化和除权权益。缺历史成交额会影响入场，期末持仓市值未扣未来清仓费。应分别研究上涨、下跌、震荡阶段，不能将回测等同可实现或未来收益。

通知默认关闭，在启动终端设置后生效：

```powershell
$env:DESKTOP_NOTIFY='1'
$env:NOTIFY_WEBHOOK='https://自己的接收端'
.\.venv\Scripts\python.exe -m monitor.scheduler
```

环境变量管理敏感URL，不提交源码；.env.example仅作说明，程序不会自动读取.env。Webhook发送JSON text字段、10秒超时；模拟不发通知。桌面提醒需要登录及系统权限，测试未实际给用户发送提醒。

## 全A股扫描（新增）

自选股监控保留原样；新增独立“全A股扫描”页面，不把5577只代码塞进自选列表。沪市主板、科创板、深市（含创业板）、北交所分别读取交易所名录；本次实测返回5577只，具体数量随名录更新变化，不能据此保证每只都有可用历史行情。接口依据AKShare官方股票名录实现：https://github.com/akfamily/akshare/blob/main/akshare/stock/stock_info.py 。

### 操作步骤

1. 更新完成后关闭并重新打开网页服务窗口，侧栏选择“全A股扫描”。原有自选股自动监控仍可单独运行。
2. 点击“更新股票名录”，查看四段名录是否都成功、数量和取得时间。如果只取得部分，会明确提示不完整，不能称为全市场覆盖。名录接口失败时可导入UTF-8 CSV（列code,name）；导入不自动认定覆盖完整。
3. 选择沪市、深市、北交所范围及是否包含ST，点击“创建本轮扫描任务”。仅做研究，包含特殊板块不代表满足交易门槛。
4. 双击 **5-启动全A股扫描.cmd**，保留终端；它只处理已创建的任务，不会自动创建其他任务。也可在网页点“手动处理一批”。默认每批最多10只/120秒，批间10秒，串行请求、不启用并发。
5. 点“刷新进度”查看已处理、待处理、候选、失败数量。暂停在当前股票处理完毕后生效，继续可续扫；关闭处理器或关机后，重启能恢复已落库进度。异常中断时会恢复正在处理的那只。
6. 每股每轮最多允许人工重试一次失败项，成功项不重扫。也可取消任务再创建新一轮。CSV可导出整轮已处理和待处理情况，结果表按100只分页。
7. 本轮结束后不会自动每天重建；需要重新创建下一轮。若预期交易日或盘中/完整日K阶段变化，旧任务会停止并标为过期，需新建，避免跨阶段结果冒充同一批实时数据。建议**15:20之后创建收盘扫描**，可利用夜间完成；先试小范围再全市场。
8. 筛到感兴趣的股票，可展开计算、加入自选，再回“行情总览”重新扫描。全市场记录明确标注扫描时状态，不保证旧候选当前依然有效；优先风险条件仍须人工核验。

### 扫描方式与边界

先取日/完整周K检查突破和回踩规则；未通过初筛不请求实时快照，标注“日K初筛（非实时）”。只有规则通过才取新鲜快照、双源交叉验证和风险计算，不降低原有价差/时间门槛。全市场默认不发桌面/Webhook通知，避免批量通知；自选股通知配置保持原样。

全市场历史优先腾讯，再新浪、东方财富；每个接口单次尝试，其他日期、新鲜度和完整K验证保持。公开源可能没有北交所等股票足够的周线，会明确数据不足或失败，不能保证所有股票都有数据。盘中缓存不能仅因为到了收盘时间就变成完整K。

一轮几千只可能耗时数小时，故障时更久，**不是全A股每5分钟实时扫描**。每股记录独立扫描时间，整轮不是同一时点快照。6只/少量自选仍由2号启动器每5分钟监控；全A股由5号启动器按队列处理，两者使用独立数据库和锁。免费源不是稳定全市场实时数据服务。

名录与进度分别保存在data/market-real.sqlite3、data/market-demo.sqlite3，模拟仅6只模拟名录，不伪装成5000多只真实数据。无需新装依赖，不下载整套数据库。随着历史缓存增加会占用本项目磁盘空间。

配置项：market_batch_size=10（1–50）、market_batch_seconds=120（10–600）、market_interval=10（1–300）。任务创建时保存参数快照，后续改参数对新任务生效。不要为了提速大幅缩短请求间隔。

完整验证与未验证项见VALIDATION.md。
